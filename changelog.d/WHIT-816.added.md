- **People can use the workspace's agents for themselves.** `GET /api/me/agents` lists the workspace's agents and which you use. `POST /api/me/agents/{id}/assignment` starts using one: your grant starts from the agent's template, limited to what you hold, with reads at most Allowed and writes at most Ask first. Change it permission by permission at `/api/me/agents/{id}/assignment/grant` (the same rows as an agent credential's grant screen), or stop with `DELETE`, which revokes its credentials. `POST /api/me/agents/{id}/credentials` issues an MCP credential that acts as that agent for you. Every signed-in member can use these; they are never MCP operations, so an agent can't grant itself or widen its own grant (migration 181; WHIT-816).
- **An agent is one principal, whatever its credentials.** A credential bound to a workspace agent reads its toolsets and grant from your use of the agent on every call, so a change applies at once to all of them, and it is refused once you stop using the agent or an admin archives it. Proposals, the activity trail and actor columns name it `agent:<id>`, not a credential's token id, and approving a proposal re-checks your grant as it is now (WHIT-816).
