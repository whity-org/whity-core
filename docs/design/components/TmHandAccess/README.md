# Mobile: hands and accessibility

- **Which hand?** (M.46) A preference, right by default, set in onboarding's gestures step or Preferences › Using Whity. It moves the **main button** in two-button bars and steppers to the thumb's side and flips which way swipe to approve goes. The tab bar and Create stay centred, and full-width buttons stay full-width.
- **Left-hand layout:** the stock count's **+** and the bottom bar's **Next item** move to the left; Decline/Approve swap so Approve is on the left.
- **Largest text size** (M.5): Whity follows the phone's accessibility sizes. Rows stack (title, then details) instead of truncating, titles wrap, and the tab bar shows icons only, with each label shown large when pressed and held. Nothing is cut off; screens scroll.
- **Screen reader order:** the header, the section, then the **whole card as one item** with a full sentence ("Billing assistant, for you, proposes: send a payment reminder to Example Café, 312 Jordanian dinars, waiting 2 days."), then Decline and Approve, then the tab bar. Amounts are read as words with the currency; agents are always introduced as agents.
- Colour is never the only signal (badges have words, tier 3 has a lock); every target is 48px or larger; motion follows Reduce motion (M.25).
